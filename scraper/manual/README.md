# 手動入力データ(scraper/manual/)

Instagram・Googleマップの「メニュー」機能だけで営業しているなど、
**公式サイトを持たずスクレイピング対象にできない店舗**の情報を、
手動で登録するための仕組み。

## 対象になる店舗の例

- 公式サイトがなく、Instagram・Googleマップのみで営業している店舗
- 公式サイトはあるが通販機能がなく、店舗限定販売(店頭でのみ購入可能)の店舗
- いずれの場合も、産地・価格等の商品情報自体は(オンライン販売ページで
  なくても)何らかの形で確認できることが選定基準
  (`scraper-discovery-workflow.md`参照)
- Instagram・Googleマップの自動取得は、利用規約上の制約(Instagram)や、
  このプロジェクトの既存方針(Googleマップは自動抽出せず外部リンク方式)
  により行わない。そのため、目視で確認した情報を人力で入力する

## scraper/explore_candidate.py との使い分け

`scraper-discovery-workflow.md`のStep 2の時点で、候補が「そもそも
スクレイピング対象になるWebサイトを持たない(Instagram/Googleマップのみ)」
と判明した場合、`explore_candidate.py`には進まず、この手動入力の
仕組みに回す。

## ファイルの置き方

`scraper/manual/shops/<店舗のスラッグ>.json` として、1店舗1ファイルで置く。
`TEMPLATE.json`をコピーして使う。

## data_source: "manual" について

自動スクレイピングされたデータには付かない目印。アプリ側の表示で、
「この情報は手動確認したものです(最終確認日: XX)」のように、
自動更新されるデータとは違うことをユーザーに伝えられるようにするための
フィールド。

## 更新頻度について

自動スクレイピングと違い、GitHub Actionsによる定期更新の対象外。
情報が古くなっていないか、`last_verified_at`を見ながら、気づいた時に
手動で見直す運用になる。
