# スクレイパー実装ログ(不具合パターン集)

新しい店舗のスクレイパーを実装するたびに、実データ検証(実際のワークフロー実行・
ブラウザ確認)で見つかった不具合とその対処をここに追記する。目的は同じ種類の
不具合を将来の店舗実装で繰り返さないこと。バグが無く素直に実装できた店舗は
記載しない(記載するのは「発見した不具合」があるケースのみ)。

フォーマット:

```
## [店舗名]（プラットフォーム、実装日）
- 発見した不具合: ...
- 対処: ...
- 影響した既存データ: ...(あれば)
```

実在確認したが実装を見送った店舗(オンラインショップが無い、閉店済み等)は
このファイルではなく`docs/not-implementable-shops.md`に記録する。

---

## HIMONYA FIVE COFFEE（BASE、2026-09-03）
- 発見した不具合: (1)商品名末尾に「(生豆Ng)」という生豆(焙煎前)重量の表記が
  付いているが、この店は注文後焙煎モデルで、実際の販売重量は焙煎後の目減りした
  値(説明文に「生豆240gを焙煎し、焙煎後は約200gとなる」等の明記あり)。生豆重量を
  そのままweight_gに使うと実際に届く量と食い違う。(2)ブレンド判定をタイトルの
  「ブレンド」の語に頼れない。単一原産地商品の多くはタイトルに国名すら無く、
  逆に9件中2件のブレンドしかタイトルに「ブレンド」を含まない。
- 対処: (1)説明文の「焙煎後は約Ng」という明記を正規表現(WEIGHT_ROASTED_PATTERN)で
  抽出し、生豆重量ではなくこちらをweight_gに採用。(2)構造化された「原産国」欄が
  「（ブレンド）」を含むかどうかでブレンド判定する方式に変更(タイトル文字列に
  頼らない)。
- 影響した既存データ: なし(新規実装時に発見)

## たまじ珈琲（WordPress + USC-e-Shop、2026-09-03）

- 影響した既存データ: たまじブレンドJOKERの1件。手動でレコードを削除し

## ライブコーヒー（おちゃのこネット(Ocnk)、2026-09-03）
- 発見した不具合: 同じOcnkクリーンURL方式(/product-list/N)の店舗でも、
  テーマのバージョンが店舗ごとに異なっていた(米本珈琲は"touch001"、
  ライブコーヒーは"touch035")。米本珈琲用に確認したDOM構造
  (`a.item_data_link`)をそのままライブコーヒーにも流用してしまい、
  実際のクラス名は`a.list_item_link`だったため一覧ページの商品が0件で
  返っていた。ローカルでのcurl事前確認では「li.list_item_cellの件数」しか
  見ておらず、内部のリンク要素クラス名まで個別に確認していなかったことが
  根本原因。
- 対処: 実ワークフロー実行時にHTMLを一時的にデバッグ出力(GitHub Actions側の
  実際のレスポンスをその場で確認)し、`a.list_item_link`が正しいクラス名だと
  特定。セレクタを修正し、デバッグコードは元に戻した。
- 影響した既存データ: なし(初回実装時に発見。0件のまま気づかず放置していれば
  店舗自体が実質的に空データとして扱われるところだった)。
- 教訓: 「同じプラットフォーム・同じURL方式」であっても、店舗ごとにテーマ
  バージョンが異なりDOM構造が食い違うことがある。一覧ページのDOM確認は
  必ず対象の店舗自身のHTMLで個別に行い、他店舗の確認結果を流用しない。

## 十一房珈琲店（手動データ登録、2026-09-04）
- 発見した不具合: 手動データのproductUrlを、同じ豆の焙煎度違い2商品
  (例:「ペルー・アンデスブルー」のフルシティロースト版とフレンチロースト版)
  に同じブログ記事URLをそのまま設定していた。aggregate_shops.pyの
  build_manual_product()はproductUrlをそのままレコードidに使うため、
  2商品が同一idを持つことになり、フロントエンドでReactのkey重複エラーが
  発生し、片方の商品が表示されない/重複表示される不具合が起きていた。
  ブラウザでの目視確認(get_page_textでの一覧表示・商品件数)だけでは
  気づきにくく、コンソールエラーの確認で発覚した。
- 対処: 同一URLを共有するペアの片方のproductUrlをnullにし、
  raw_name由来のフォールバックid(`manual:{shop_id}:{raw_name}`、
  焙煎度をraw_nameに含めているため一意)を使わせるよう修正。
- 影響した既存データ: 十一房珈琲店の25件中4組(ペルー/タンザニア/
  コスタリカ/ザンビア、各2件ずつ)。
- 教訓: 手動データで同一商品ページに複数バリエーション(焙煎度・重量等)が
  併記されている場合、productUrlをそのまま複数レコードに使い回すと
  id衝突を起こす。バリエーションごとに異なるproductUrl(無ければnull)を
  設定し、raw_name側でユニーク性を保証すること。
