# 風味語彙(アプリ独自)の更新手順

作成: 2026-11-10。SCA/WCRのフレーバーホイールの権利関係(`docs/flavor-wheel-license.md`)を受けて、ホイールの構造・用語一覧に依存しない、アプリ独自の語彙に作り替えた。

## どこにあるか
- **データ: `src/data/flavorVocabulary.json`** — 語彙の中身は、ここだけを直す。
- 読み込み: `src/data/flavorVocabulary.js`(jsonを使いやすい形にするだけ。通常は触らない)
- 使う場所(自動で反映される): 風味の入力(`FlavorPicker`)、検索の絞り込み(`FilterSheet`)、商品説明からの自動分類(`utils/flavor.js`)、英語表示(`i18n/en.js` が `FLAVOR_EN` を読む)
- 検査: `npm run flavor:check`(形の誤りを調べ、商品説明での各語の出現数と、分類できた割合を表示する)

## 出典・選び方(記録)
- アプリ独自の分類。SCA/WCRのホイールの構造(階層・グループ名・用語の一覧)は使っていない。
- カテゴリの名前・順序・数と、語の一覧は、2026-11-10時点の商品説明24,849件での出現数と、日本語で一般に使われる表現から決めた。「質感・後味」は、商品説明での出現が多い語(コク・余韻など)から立てたカテゴリ。
- 「その他」のような否定的に受け取られるカテゴリは置かない。
- 一般語(フルーティー、チョコレート、レモン など)は共通して使われる言葉で、特定の資料の用語リストをなぞったものではない。

## 形式
```
categories[]: { id, ja, en, color(#RRGGBB), match[](カテゴリ全体の別表記), terms[] }
terms[]:      { ja, en, match[](説明文から探す別表記。小文字で比較。英語・かな・漢字の言い換え), generic(省略可。ほとんどの商品に出る一般的な語。true にすると、商品カードの風味タグで後ろに回る) }
legacy:       { "<旧い語>": { category(id。無ければ中立色), en } }
```
- 利用者の記録には、語(日本語)だけが保存される。画面の色・英語は、表示のたびにここから引く。

## よくある作業
- **語を足す**: 該当カテゴリの `terms` に `{ "ja": "...", "en": "...", "match": [...] }` を足す。`match` は、説明文でよく見る別の書き方(例: `桃` → `ピーチ`, `peach`)。1文字の別表記は誤判定しやすいので不可(検査で止まる)。
- **語を直す・消す**: 利用者がすでにその語で記録しているかもしれない。**消さずに `legacy` へ移す**(`category` と `en` を付ける)。そうすれば記録は、そのまま表示される。現在の語と legacy の重複は、検査で止まる。
- **カテゴリを足す・並べ替える**: `categories` に足す(順番がそのまま画面の順)。`id` と `en` は重複不可、`color` は #RRGGBB。
- **語の取捨選択の目安**: `npm run flavor:check` が出す、語ごとの出現数を見る。出現がほとんど無い語も、入力の選択肢としては使える。
- 直したら、`npm run flavor:check` と `npm run i18n:check` を通す。

## 商品の風味タグ(詳細分類)
- 商品のテイスティングノートに、語(または別表記)が載っていれば、その語を「詳細分類」のタグとして付ける(例: 「柑橘」「ジャスミン」)。タグの色はカテゴリの色。
- 一覧カードは最大6件(特定の語 → 一般的な語(generic) → 語までは特定できず、カテゴリだけに分類されたもの の順)。残りは「ほか○件」と表示し、全件は商品の詳細画面にカテゴリごとに出る。
- 絞り込み(検索の「絞り込み」→「風味」)は、大分類(カテゴリ)と詳細分類(語)のどちらも選べる。選んだもののどれかに該当する商品を出す。詳細分類の一覧は、自動で付く語だけ(`"auto": false` の語は出さない)。

## 酸味は、利用者が判断する語(自動で付けない)
- 「酸味」「明るい酸味」は、焙煎度や淹れ方でも変わるため、商品の説明文からは自動で付けない(JSONの `"auto": false`)。入力の選択肢(テイスティングノート・ログ)には出る。
- 同じ理由で、カテゴリ全体の別表記から英語の `sour` も外した。他の語(爽やか・ワイン・発酵 など)は、通常どおり自動で付く。
- 他の語も `"auto": false` にすれば、同じ扱いにできる。

## 否定の除外(「無い系」のみ、2026-11-10導入)
- 語の**直後で否定されている出現**(例:「甘さがなく」「コクはない」「ベリーを感じない」「強くない」「〜なし」)は、その語が「ある」とは数えない。語のすべての出現が否定のときだけ、タグを付けない。
- 実装: `src/utils/flavorMatch.js`。語と否定が直接つながる形だけを見る(「コクがあって飽きない」の「コク」は否定しない)。
- 「控えめ」「少ない」「抑えた」などの弱い表現は除外しない(まだ「ある」と数える)。
- 導入後の実データでの除外は、約6件(商品説明24,849件中)。酸味を自動で付けなくしたため、影響の大半(酸味)が、そもそも対象外になった。

## 注意
- 自動分類は、商品説明に語が含まれるかを調べるだけ(部分一致)。「苦味」「酸味」のような語は多くの商品に出るので、分類語にするかどうかは、結果を見て決める(「苦味」は分類語にしていない)。
- 公式のホイール(SCA/WCR)を載せたい、または語を合わせたいときは、ライセンスの確認が先(`docs/flavor-wheel-license.md`)。
