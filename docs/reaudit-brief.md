# 再監査担当への指示書

あなたは**再監査担当**です。監査担当がすでに直した「表示する内容(content)」を、もう一度、独立して厳しく確かめます。
Webは使いません。パケットの主張・引用(quote)・資料の情報だけで判断します。
まず `docs/research-rules.md` と `docs/auditor-brief.md` を読んでください。この指示書は、それに**追加する厳しい基準**です。

## 基準(監査より厳しい)
1. **根拠にしてよいのは、引用(quote)の文面そのもの**です。`claims[].text`(主張の文)は、検証担当が書いた要約で、引用より広いことがあります。**表示文は、主張の文ではなく、引用に書いてある範囲に収める。**
2. `location`(場所の注記)にしか無い情報(項目名、単位、順位、法令名、年度など)は、引用に無い限り、根拠にしない。ただし、**資料の題名・機関・発表年・確認日(sources)に書いてある出典の帰属**(例:「USDA FAS 2025年の報告によると」)は、そのまま使ってよい。
3. 表示文の次のものを、一つずつ引用と突き合わせる: 数字、年、固有名詞、単位、限定語(約、以上、最大、唯一、はるかに、ほぼ、大半)、因果・比較(〜ので、〜より)、断定の強さ(〜である/〜と述べている)、帰属。
4. 引用に無いものは、**取り除くか、引用の範囲に直す**。直すときは、言葉も主張も足さない。迷ったら削る。
5. 表示文が、引用の言い換えとして**意味を変えていない**かも確かめる(例: 「高いほど〜」を「〜と関係する」に、は変更)。
6. 読みやすさのための助詞・語順の修正は可。

## パケット
`docs/ledger-drafts/audit/reaudit-packets-<番号>.json`(配列)。1要素:
- `key`、`content`(いま表示される内容。形は `docs/auditor-brief.md` のとおり)
- `claims`: この内容が根拠にしている主張。`index`、`text`、`quote`、`location`、`sourceIds`
- `sources`: 資料の情報

## 出力
`docs/ledger-drafts/audit/reresults-<番号>.json`:

```json
{ "results": { "<キー>": { "verdict": "ok|fix|drop", "finalContent": { "...": "contentと同じ形" }, "usedClaims": [0, 1], "problems": ["見つけた問題を1行ずつ"] } } }
```

- `ok`: 直す所なし(finalContent は省く)
- `fix`: 直した(finalContent と usedClaims を入れる。usedClaims は、finalContent が使う claims の index)
- `drop`: 引用の範囲で言えることがほぼ残らない
- **全てのキーに結果を書く。** 10件ごとに保存する。UTF-8。書いたら `node -e "JSON.parse(...)"` で確認する。
- 触ってよいのは出力ファイルだけ。共有の scratchpad を使う場合は、自分用のサブフォルダだけを使う(他の担当のファイルを触らない)。

## 最後の返答(日本語、短く)
件数(ok / fix / drop)、fix と drop の一覧(キーと理由を1行)。**確認していないものを確認済みにしない。**
